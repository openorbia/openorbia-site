# OpenOrbia SEO audit, 2026-11-20

Scope: the Search Console, Bing, Cloudflare and technical SEO checklist, three days before Launch Week 1 (Mon Nov 23, 12:00 AM
Central). Earlier audit: `SEO_AUDIT.md`. Fix log: `SEO_FIXES.md`. Owner steps: `SEARCH_CONSOLE_CHECKLIST.md`.

## Executive summary

- **The public site is technically clean.** 63 sitemap URLs and 2 extra crawled URLs: every page returns 200, no broken internal
  links or assets (42 checked), no orphan pages, every page has exactly one `<h1>`, a self-referencing canonical, a meta
  description and Open Graph tags, no accidental `noindex`, no duplicate titles or descriptions.
- **P0: the 25 Week 1 launch pages are not live.** The live database is empty, so `/launch/<slug>/` returns 404 and the sitemap
  lists 0 launch URLs even though the lineup was due to be announced on Wed Nov 18. The fix is the owner's: give the Cloudflare API
  token D1 Edit, then run the **Seed launches** workflow (steps in the private ops repo, `NEXT-STEPS.md`).
- **P1: `www.openorbia.com` serves a full duplicate of the site (200, no redirect).** Canonical tags point at the apex, which
  limits the damage, but a 301 is the right fix. A Cloudflare Redirect Rule is proposed below and needs owner approval.
- **Search Console is healthy and recorded.** Verified owner; no manual actions or security issues; sitemap read successfully;
  61 pages indexed; every "not indexed" reason is expected. Last 28 days: 21 clicks, 969 impressions, CTR 2.2%, position 32.8. The
  www copies already take impressions and 5 www URLs are indexed, which confirms the P1. The category pages are not yet known to
  Google. Cloudflare was not signed in, so its dashboard items stay NOT VERIFIED.
- **P1: Bing has no sitemap.** Bing Webmaster Tools (read later the same day) lists no submitted sitemap, only 5 indexed URLs, and
  shows both `/launch-list/` and `/category/careers/` as "Discovered but not crawled". Submitting `sitemap.xml` there needs owner
  approval.
- **Fixed in this branch (low risk):** the Launch List now carries `CollectionPage` + `ItemList` structured data (it had none),
  and its meta description was cut from 180 to 155 characters.

## Method and evidence

All checks ran on 2026-11-20 against production (`https://openorbia.com`) from a plain HTTP client, plus repository inspection
on `main` at `461ae82`. A crawler script fetched `sitemap.xml`, then every page in it and every same-site link found in the HTML
(no JavaScript run), and sent a HEAD request to every same-site asset. Nothing was submitted to any search engine.

Search Console was then read (read-only, nothing submitted or requested) in the owner's own signed-in Chrome through Claude in
Chrome, after the owner signed in; Bing and Cloudflare were not signed in there either.

Browser access at first: the Claude desktop app's built-in browser was available. It was **not** signed in to Search Console
(`search.google.com` showed the public "Start now" page), Bing Webmaster Tools (public "about" page) or Cloudflare (login page).
No passwords, cookies or tokens were asked for. The PageSpeed Insights API returned "Quota exceeded" (no API key) and the
pagespeed.web.dev page did not finish, so Lighthouse and field Core Web Vitals are NOT VERIFIED.
